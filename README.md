# magpie user-registry

A copy of [magpie-community/plugins](https://github.com/magpie-community/plugins)'s
`registry.json`, plus the packages that are not in it.

## Why this exists

magpie fetches its community plugin list from **one** URL and replaces its cached copy
wholesale, every few hours. A package that is not in that list still installs and
works, but its card shows only the npm or GitHub metadata:

| Card element | Comes from the registry | Without an entry |
|---|---|---|
| Title | `name` | falls back to the package name |
| Licence | the entry | not shown |
| Source button | the entry | not shown |
| Summary | `summary` | the npm description |

Hand-editing `~/.cache/magpie/plugin-market.json` does not last — measured on this
machine, a patch was gone within one second of magpie's first fetch.

This repository serves that list with **the official entries untouched plus my own**,
so a user gets complete cards by setting one variable. It is a stopgap: it asks the
user to configure something, and it asks a maintainer to run a workflow.

The underlying problem is written up here, with the directions I think would remove
the need for this repository entirely:
**[magpie-community/plugins#394](https://github.com/magpie-community/plugins/issues/394)**

## Using it

Point magpie at this registry:

```sh
export MAGPIE_PLUGIN_MARKET=https://raw.githubusercontent.com/MYCF711/magpie-registry/main/registry.json
```

Windows, once for your user account:

```powershell
[Environment]::SetEnvironmentVariable(
  "MAGPIE_PLUGIN_MARKET",
  "https://raw.githubusercontent.com/MYCF711/magpie-registry/main/registry.json",
  "User"
)
```

Restart magpie. The official entries keep working; the added ones now render fully.

`registry.json` is regenerated by [the sync workflow](.github/workflows/sync.yml)
every hour: it fetches the official list and appends what `local.json` holds. An
official entry whose package is also in `local.json` is dropped, so a package that
later joins the community list does not appear twice.

## Adding your own

Fork, edit `local.json`, and let the workflow rebuild `registry.json`:

```json
{
  "plugins": [
    {
      "package": "your-package-name",
      "name": "Card title",
      "providers": ["your-provider"],
      "community": true,
      "summary": {
        "en": "One sentence.",
        "zh": "一句话。"
      }
    }
  ]
}
```

`package` must equal the package's `name` in its `package.json` — that is what
magpie matches an installed plugin against.

## The alternative

If you would rather not run a registry, package authors can write the entry into
magpie's own cache from inside the plugin. That is what
[the template's `self-register.mjs`](https://github.com/MYCF711/magpie-plugin-template/blob/main/src/self-register.mjs)
does, and it needs no configuration at all — at the cost of rewriting a cache file
that magpie replaces every few hours, so it has to re-apply itself.

Use the registry when you want it permanent and shared; use self-registration when
you want it to work without anyone setting anything up.
